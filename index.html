12-Module JCL Review

The 6 Phases of JES2 Job Processing (And Where Failures Occur)

1. INPUT PHASE

JES reads JCL from Internal Reader (INTRDR), TSO SUBMIT, or scheduler into JES2 Spool (SYS1.HASPACE) and assigns a Job ID (JOBnnnnn). TYPRUN=JCLHOLD stops the job right here.

2. CONVERSION PHASE

Converter/Interpreter expands PROCs (JCLLIB), resolves symbolics, merges overrides, and converts JCL into internal text (C/I). JCL Syntax Errors & TYPRUN=SCAN happen here!

3. EXECUTION PHASE

Initiator selects job based on CLASS & PRTY. Allocation routines allocate datasets step-by-step, attach load module (S806 at attach), run program (S0C7/S0C4), and write extents (SB37/SD37).

4. OUTPUT PHASE

SYSOUT datasets (JESMSGLG, JESJCL, JESYSMSG, SYSOUT=*) are grouped by MSGCLASS characteristics for spool viewing (SDSF ST / O).

5. HARDCOPY PHASE

Output classes routed to physical/virtual printers, external writers, or archival tools (SAR / ViewDirect / Control-D).

6. PURGE PHASE

Once all SYSOUT datasets are processed or deleted, JES2 frees the spool space and purges the job record (HASP250 JOB PURGED).

Valid Rule: Break after a comma before column 71, start the next line with // in cols 1–2, leave column 3 blank, and resume the continued parameter anywhere between Columns 4 and 16 (inclusive).

COLS 1–2: IDENTIFIER

// for JCL statements, /* for instream data delimiter (or JES2 control statements), //* for comments.

COLS 3–10: NAME FIELD

1 to 8 characters (A–Z, 0–9, and national chars @ # $). First character must be alphabetical or national. Followed by at least 1 blank (Col 11).

COLS 12–15: OPERATION

JOB, EXEC, DD, PROC, PEND, JCLLIB, INCLUDE, SET, IF/ENDIF. Preceded & followed by a space.

COLS 17–71: OPERANDS

Positional parameters must precede keyword parameters. Separated by commas with no embedded spaces (unless inside quotes).

CONTINUATION (COLS 4–16)

End line before col 72 with a comma ,. Next line starts with // + space, and continues between Columns 4 and 16. Coding in Col 17 treats the operand as a comment or causes a JCL error!

COLS 72 & 73–80

Col 72: Non-blank needed only when splitting a quoted string across lines (continue string in Col 16 of next line). Cols 73–80: Sequence numbers (ignored by JES, watch out for ISPF NUM ON putting numbers inside data!).

★ 5-Yr Interview Anchor — Positional vs Keyword Parameters:
  • On JOB: Accounting Information (1st positional) and Programmer Name (2nd positional, max 20 chars). If Accounting Info is omitted, you must code a leading comma: //JOB1 JOB ,'R.SHARMA',CLASS=A.
  • On EXEC: PGM=name or PROC=name (or bare procname) is positional and must come first.
  • On DD: * , DATA , DUMMY , DYNAM are the 4 positional parameters on a DD statement.
★ Senior Missing Notes — JES2 / JOB lifecycleSenior note

Missing senior point: TYPRUN=SCAN validates JCL through the converter; it does not execute the job or perform all interpreter-time validation. Also remember JES conversion errors (IEFC*) and interpreter/allocation errors (IEF*) are different diagnostic layers.

Short JCL example
//CHKJCL  JOB ("ACCT"),CLASS=A,MSGCLASS=X,TYPRUN=SCAN
//STEP1   EXEC PGM=IEFBR14

MSGLEVEL=(statements, messages)

Controls what prints in the JES Job Log (JESJCL / JESYSMSG):

  • Statements (0–2): 0 = Only JOB statement; 1 = All JCL + expanded PROC statements & symbolics; 2 = Only input JCL (no expanded PROCs).
  • Messages (0–1): 0 = JCL/Allocation messages only if job abends; 1 = All allocation/termination/SMS messages regardless of outcome.
  • Production standard is MSGLEVEL=(1,1).

TYPRUN=(SCAN | HOLD | JCLHOLD | COPY)

  • TYPRUN=SCAN: Checks syntax errors only without executing or allocating datasets. (Note: Does NOT catch dataset-not-found or runtime errors; JSCAN/PRO/JCL is preferred in enterprise shops).
  • TYPRUN=HOLD vs JCLHOLD: JCLHOLD holds the job before JES2 JCL conversion/proc expansion; HOLD converts JCL first and holds prior to execution.
  • TYPRUN=COPY: Copies source JCL directly to the MSGCLASS sysout queue without running.
TIME=1440 / TIME=NOLIMIT S322 & S522

5-Yr Trick Question: Why does TIME=1440 (24 hours) do more than just give 24 hours of CPU?
Because in z/OS, TIME=1440 or TIME=NOLIMIT gives unlimited CPU time (prevents S322) AND disables SMF Continuous Wait Time limits (prevents S522 wait timeout)! In Contrast, TIME=MAXIMUM allows 357,912 minutes of CPU time but still enforces wait-time limits.

REGION=0M (or 0K) Architecture S80A / S878 / S822

REGION=0M grants the step all available private virtual storage both below the 16MB line (24-bit, typically ~8–10MB max) and above the 16MB line (31-bit Extended Private Area, up to 2GB), unless capped by an installation IEFUSI SMF exit. If JOB and EXEC both specify REGION, the JOB card overrides the EXEC card!

★ Passing Data from JCL to COBOL (PARM vs PARMDD vs SYSIN)

1. EXEC PARM='...'

Max 100 characters. Passed by reference to COBOL LINKAGE SECTION preceded by a 2-byte binary halfword length field (PIC S9(4) COMP) + PROCEDURE DIVISION USING LK-PARM.

2. EXEC PARMDD=ddname (z/OS 2.1+)

Overcomes the 100-byte limit! Points to a DD card containing long parameter strings up to 32,760 characters, still received via LINKAGE SECTION.

3. SYSIN DD *

No 100-byte limit. Read inside COBOL PROCEDURE DIVISION via ACCEPT WS-VAR FROM SYSIN (or defined as a standard sequential file). Does not use Linkage Section.

★ Senior Missing Notes — JOB & EXECSenior note

Missing senior point: JOB-level and EXEC-level parameters have different scope. A JOB-level TIME/REGION can establish job-wide limits, while EXEC can specify step-level values; installation exits and system limits can still constrain the effective value. For parameter passing, PARM is limited in length; use PARMDD/SYSIN when the interface requires more data.

Short JCL example
//STEP1   EXEC PGM=MYPROG,PARM="RUN=FULL"
//SYSOUT   DD SYSOUT=*

The Legacy COND Parameter

Syntax: COND=((code,operator[,stepname][.procstepname]),...,EVEN|ONLY)

  • Maximum comparisons: Up to 8 condition tests per EXEC statement. If any single condition evaluates to TRUE, the step is BYPASSED.
  • JOB-level vs EXEC-level COND: If a JOB-level COND is satisfied (TRUE), all remaining steps in the job are terminated immediately.
  • COND=(0,LE) or COND=(0, LT): Since 0 is always <= any valid RC (0–4095), COND=(0,LE) is always TRUE and guarantees the step is bypassed (used in production to comment-out a step without deleting JCL).
  • COND=EVEN: Execute this step even if a previous step abended (unless an accompanying RC test is TRUE).
  • COND=ONLY: Execute this step only if a previous step abended.

Modern IF / THEN / ELSE / ENDIF

Positive Boolean logic: Executes the THEN clause when the expression is TRUE.

  • Supports nesting up to 15 levels deep.
  • Can test specific return codes (STEP1.RC = 4), abends (STEP1.ABEND or ABENDCC=S0C7), and whether a step actually ran (STEP1.RUN = TRUE).
  • Post-Abend Behaviour: If a prior step abends, an IF block is skipped unless the expression explicitly references ABEND, ABENDCC, or ¬ABEND!
//CHKSTEP  IF (STEP01.RC <= 4 & STEP01.RUN) THEN
//STEP02   EXEC PGM=PYRL020
//         ELSE
//NOTIFY   EXEC PGM=ERRMAIL,COND=EVEN
//         ENDIF
★ Senior Missing Notes — COND / IFSenior note

Important distinction: IF/THEN/ELSE is positive logic (TRUE selects THEN), while COND is a bypass test (TRUE causes the step to be bypassed). IBM also documents that IF structures normally do not execute their contained steps after an abend unless ABEND/ABENDCC/¬ABEND is referenced or an appropriate COND condition is used.

Short JCL example
//STEP1 EXEC PGM=PGMA
//STEP2 EXEC PGM=PGMB,COND=(4,LT,STEP1)

DISP=(status, normal-disp, abnormal-disp)

  • Status: NEW (exclusive, creates), OLD (exclusive existing), SHR (shared read), MOD (appends to existing OR creates if not cataloged and no VOL=SER coded).
  • Normal Termination: DELETE, KEEP, CATLG, UNCATLG, PASS.
  • Abnormal Termination: DELETE, KEEP, CATLG, UNCATLG (PASS is NEVER allowed in abnormal!).
  • Default Rules (Memorize!):
    • Entire DISP omitted ➔ defaults to DISP=(NEW,DELETE,DELETE) (temporary work file).
    • DISP=NEW ➔ (NEW,DELETE,DELETE).
    • DISP=SHR ➔ (SHR,KEEP,KEEP); DISP=OLD ➔ (OLD,KEEP,KEEP).
    • If 3rd subparameter (abnormal) is omitted, it defaults to whatever the 2nd subparameter (normal) is! (Except if normal is PASS, abnormal defaults to DELETE for NEW or KEEP for OLD/SHR).

SPACE, Extents & BLKSIZE=0

  • SPACE=(CYL,(pri,sec,dir),RLSE,CONTIG,ROUND):
    • RLSE releases unused space on normal CLOSE (ignored if step abends!).
    • 3390 Geometry: 1 Track = 56,664 bytes; 1 Cylinder = 15 Tracks.
  • Extent Limits: Standard basic/large PS & PDS datasets allow max 16 extents per volume. SMS Extended Format / PDSE allows up to 123 extents per volume (and up to 59 volumes).
  • Why BLKSIZE=0? Instructs SMS/SDB (System-Determined Blocksize) to calculate the optimal half-track blocksize for the target device at allocation/open time (e.g., for LRECL=80 on 3390 DASD, 27,920 bytes [349 records/block], achieving ~98.5% track utilization; max 3390 half-track is 27,998; max tape is 32,760).

★ Dataset Concatenation & DD DUMMY Traps

1. Overriding the Nth dataset in a Concatenated DD inside a PROC: Keep empty // DD cards for every preceding dataset you want to leave untouched!
2. The DD DUMMY / DSN=NULLFILE Concatenation Trap: If you code // DD DUMMY as the 2nd dataset in a 4-dataset concatenation, datasets 3 and 4 are completely ignored because EOF is signaled as soon as the DUMMY allocation is reached! 

//* OVERRIDING ONLY THE 3RD DATASET IN PROCSTEP 'PSTEP1' DD 'STEPLIB':
//STEP01   EXEC MYPROC
//PSTEP1.STEPLIB DD
//               DD
//               DD DSN=TEST.PATCH.LOADLIB,DISP=SHR
★ Senior Missing Notes — DD / DISP / SPACESenior note

Senior point: DISP controls the dataset disposition, not the volume disposition. Also be precise with defaults: DISP=OLD and DISP=SHR both imply KEEP on normal and abnormal termination, but their status values remain OLD and SHR respectively.

Short JCL example
//OUT DD DSN=USER.REPORT,DISP=(NEW,CATLG,DELETE),
//       SPACE=(CYL,(5,2),RLSE),UNIT=SYSDA

Instream vs Cataloged PROCs & JCLLIB

  • Instream PROC: Begins with //name PROC and must end with // PEND. Maximum 15 instream PROCs per job.
  • Cataloged PROC: Stored as a member in a PDS/PDSE procedure library. Specify custom search order right after the JOB card using //PROCS JCLLIB ORDER=(PROD.PROCLIB,TEST.PROCLIB) (up to 15 libraries).
  • What is forbidden inside a PROC? JOB, JOBLIB, JCLLIB, //*, DD * / DD DATA (prior to z/OS 2.1), and nested instream PROCs. (Note: z/OS 2.1+ now allows instream DD * inside cataloged PROCs!).

Golden Rules of EXEC & DD Overrides

  • EXEC Parameter Override: //S1 EXEC MYPROC,REGION.STEP1=0M,PARM.STEP2='DEBUG'. Notice that PGM= cannot be overridden unless it was coded as a symbolic (PGM=&PROG)!
  • DD Override Sequence: Overriding DD statements must appear in the exact step order defined in the PROC. Within the same step, existing DDs can be overridden in any order, followed by any brand-new DD cards added to that step.
  • Nullifying DCB vs Other Parameters: To nullify a parameter on an override, code PARAM= (e.g. VOL=). To nullify a DCB subparameter, you must prefix with DCB= (e.g. DCB=BLKSIZE=).
★ The Classic 5-Yr S806 Interview Question (JOBLIB + STEPLIB):
If JOBLIB contains module PGMA, and STEP01 also defines a STEPLIB that does not contain PGMA, what happens?
Answer: The step fails with S806-04 Abend (Module Not Found)! When STEPLIB is present on a step, z/OS completely ignores JOBLIB for that step and goes straight from STEPLIB to LPA / LINKLIST.
★ Senior Missing Notes — PROCs / overrides / librariesSenior note

Important lookup rule: when STEPLIB is present for a step, JOBLIB is not searched for that step. For cataloged procedures, JCLLIB controls procedure-library search order; it does not define program-load libraries. Keep these two concepts separate in interviews.

Short JCL example
//MYJOB JOB ...
//LIBS JCLLIB ORDER=(DEV.PROCLIB,PROD.PROCLIB)
//STEP EXEC MYPROC

GDG Architecture & IDCAMS Definition

Absolute generation name: HLQ.PAYROLL.GDG.G0001V00 (GnnnnVnn).

  • LIMIT: Standard GDG allows 1 to 255 generations (z/OS 2.2+ GDGEXTENDED supports up to 999 generations).
  • NOEMPTY (Standard) vs EMPTY: When LIMIT is exceeded, NOEMPTY uncatalogs only the oldest generation; EMPTY uncatalogs ALL existing generations!
  • SCRATCH vs NOSCRATCH: Once uncataloged, SCRATCH physically deletes the dataset from the DASD VTOC; NOSCRATCH leaves the dataset on disk uncataloged.

Relative Number Resolution within Same Job

Crucial Interview Question: If STEP1 creates MY.GDG(+1), how do you read that exact dataset in STEP2 of the same job?

Answer: You must still refer to it as MY.GDG(+1) with DISP=SHR! Why? Because JES resolves relative generation numbers against the catalog when the job starts (or locks the base index for the life of the job). It only rolls over to (0) for subsequent jobs!

Reading All Generations Together: Code the GDG Base Name without any generation number (DSN=MY.GDG,DISP=SHR). When a GDG base name is used without a generation number, the default order is USECATLG. GDGORDER=LIFO reads newest to oldest; GDGORDER=FIFO reads oldest to newest.

★ Senior Missing Notes — GDGSenior note

Senior point: relative GDG references depend on the applicable GDGBIAS rules; do not treat (+1) → (0) as a universal restart rule. Distinguish GDGBIAS=JOB from GDGBIAS=STEP. Also distinguish the GDG base definition from the individual generation datasets.

Short JCL example
//STEP1 EXEC PGM=IEFBR14
//NEWGDG DD DSN=USER.PAYROLL.GDG(+1),DISP=(NEW,CATLG,DELETE)
//STEP2 EXEC PGM=MYPROG
//IN     DD DSN=USER.PAYROLL.GDG(+1),DISP=SHR

QSAM & VSAM Buffer Tuning in JCL

  • DCB=(BUFNO=30) (Sequential QSAM): Tune BUFNO from measured I/O behavior; larger buffering can improve sequential I/O, but the optimum depends on workload and system configuration.
  • AMP=('BUFND=60,BUFNI=15') (VSAM KSDS):
    • Sequential VSAM processing: Increase Data Buffers (BUFND) so an entire Control Area (CA) can be read in one I/O chain.
    • Random/Dynamic VSAM processing: Increase Index Buffers (BUFNI) so index set & sequence set CIs remain resident in memory.

FREE=CLOSE & UNIT=AFF

  • FREE=CLOSE (Releasing CICS/Online Locks Early): Normally, a dataset allocated to a step remains enqueued (SYSDSN ENQ) until the entire step terminates. Coding FREE=CLOSE on the DD statement releases the dataset lock the exact millisecond the COBOL program executes CLOSE file-name, allowing CICS regions or other jobs to access it immediately while the batch step continues running!
  • UNIT=AFF=ddname (Unit Affinity): Forces multiple tape datasets in the same step (which are not opened simultaneously) to share the same device or device group, subject to allocation rules, reducing tape mount contention.
★ Senior Missing Notes — Performance / I/OSenior note

Senior point: tuning JCL parameters should be evidence-driven. BUFNO/AMP can affect buffering, while FREE=CLOSE releases a dataset allocation when the step closes it; these are not substitutes for fixing inefficient application I/O.

Short JCL example
//STEP1 EXEC PGM=SORT
//SORTIN DD DSN=USER.BIG.INPUT,DISP=SHR,BUFNO=20
1. //CEEDUMP DD

Language Environment (LE) Dump: Formatted, human-readable dump showing exact COBOL statement number, program offset, and Working-Storage variables. Best for modern Enterprise COBOL!

2. //SYSUDUMP DD

Formatted User Virtual Storage Dump: Prints PSW, General Purpose Registers (0–15), load module addresses, and user storage in hex.

3. //SYSMDUMP DD

Unformatted Machine-Readable Dump: Written to a sequential dataset (RECFM=FBS,LRECL=4160) for analysis by IPCS, Fault Analyzer, or Abend-AID.

4. //SYSABEND DD

User + System Nucleus/SQA Dump: Includes everything in SYSUDUMP plus system control blocks, LPA, and I/O buffers (huge output; rarely used in application jobs).

★ Senior Missing Notes — Special DD / dumpsSenior note

Senior point: CEEDUMP is associated with Language Environment diagnostics, while SYSUDUMP/SYSABEND/SYSMDUMP are different dump mechanisms with different detail/processing characteristics. Choose the dump DD based on the failure and diagnostic need rather than treating them as interchangeable.

Short JCL example
//STEP1   EXEC PGM=MYPROG
//SYSUDUMP DD SYSOUT=*
//CEEDUMP  DD SYSOUT=*

★ Why Do Senior Shops Prefer IKJEFT1B Over IKJEFT01 for COBOL-DB2 Batch?

Because a COBOL-DB2 program runs under the TSO Terminal Monitor Program (TMP) via the DSN command processor, standard IKJEFT01 often masks non-zero COBOL RETURN-CODE values or converts program abends into a generic RC=12 (causing downstream JCL COND/scheduler checks to misbehave!).

1. IKJEFT01 (Standard TMP)

If the COBOL subprogram abends, TSO intercepts it, flushes the remaining SYSTSIN stack, and often ends the step with a normal completion code (RC=12) instead of flagging a true JCL Abend to the scheduler.

2. IKJEFT1A (System Abend Focus)

Propagates System Abends (like S0C7) and passes the program return code when a command ends with a non-zero RC, stopping execution immediately.

3. IKJEFT1B (Gold Standard)

Propagates BOTH System Abends AND User Abends (e.g., U4038 / ILBOABN0) AND passes the exact COBOL MOVE 8 TO RETURN-CODE directly to the JCL step RC!

DFSORT High-Frequency Interview Patterns

  • Execution Pipeline Order: INCLUDE/OMIT ➔ INREC ➔ SORT/SUM ➔ OUTREC ➔ OUTFIL. Always filter with INCLUDE/OMIT and trim record length in INREC before sorting!
  • Splitting Files (OUTFIL):
    • SPLIT: Round-robin distribution (Record 1 to File 1, Rec 2 to File 2, Rec 3 to File 1...).
    • SPLITBY=n: Rotates every n contiguous records across output DDs.
    • SPLIT1R=n: Writes contiguous blocks of n records to each file once without wrapping around.
  • Reporting Totals (TRAILER1): Use OUTFIL REMOVECC,TRAILER1=('TOTAL:',COUNT=(M11,LENGTH=8),TOT=(15,5,PD,M11,LENGTH=12)) to build trailer record counts & hash totals without COBOL!

ICETOOL Essential Operators

  • SELECT: Filters by key frequency using ALLDUPS, NODUPS, FIRST, LAST, HIGHER(n), LOWER(n), EQUAL(n), plus DISCARD(ddname) to capture rejected records simultaneously!
  • SPLICE: Horizontal join/merge of fields from multiple records sharing the same key (ON(pos,len,type) WITH(pos,len)).
  • OCCUR: Prints a frequency histogram of distinct key values and how many times each occurs.
  • COUNT: Counts records and sets step return code (EMPTY RC4 or HIGHER(1000) RC8).
★ Senior Missing Notes — DFSORT / ICETOOLSenior note

Senior point: DFSORT control statements are not JCL statements. JCL allocates DD names and invokes SORT; SORT/INCLUDE/OUTREC/OUTFIL/JOINKEYS are DFSORT control statements read from SYSIN. JOINKEYS requires one JOINKEYS statement for each input file.

//SORTJNF2 DD DSN=APP.ORDERS,DISP=SHR

★ 5-Yr Production Trap: Why Does Deleting a Dataset with IEFBR14 Sometimes Stall for 20 Minutes?

If a dataset has been archived by DFSMShsm to ML2 tape (MIGRAT2), allocating it on a DD card in IEFBR14 with DISP=(MOD,DELETE,DELETE) forces HSM to mount the tape and recall the entire dataset back to primary DASD just so allocation can immediately delete it!
Senior Fix: Delete migrated datasets using IDCAMS DELETE dsn (or HDELETE), which intercepts the catalog entry and deletes the migrated copy directly without recalling it!

IEBCOPY: COPY vs COPYMOD & IEHPROGM/IEHLIST

  • COPYMOD in IEBCOPY: Must be used instead of COPY when copying Load Modules between libraries with different BLKSIZEs (reblocks load modules and avoids S106 fetch errors).
  • IEBGENER Email via SMTP: Route //SYSUT2 DD SYSOUT=(B,SMTP) and pass standard RFC 822 headers (HELO, MAIL FROM:, RCPT TO:, DATA) in SYSUT1.
  • IEHLIST: Lists PDS directory (LISTPDS) or Volume Table of Contents (LISTVTOC).

IDCAMS LASTCC vs MAXCC & VERIFY

  • LASTCC: Return code of the immediately preceding IDCAMS command.
  • MAXCC: Highest return code of any command executed so far in the IDCAMS step.
  • VERIFY DATASET(vsam.ksds): Compares End-of-Data (EOD) and High-Used RBA in the VSAM catalog against the physical dataset control blocks and closes an improperly closed VSAM file (fixes VSAM File Status 97!).
★ Senior Missing Notes — IBM utilitiesSenior note

Senior point: utility JCL is usually about the DD contract as much as the program name. For utilities such as IDCAMS, ICETOOL and IEBCOPY, validate the utility control statements separately from JCL syntax; TYPRUN=SCAN does not prove that utility control cards are semantically correct.

The 5-Point Production Restart Checklist

  1. Dataset Cleanup (`NOT CATLGD 2` prevention): Check if the abended step cataloged any output datasets (`DISP=(NEW,CATLG,CATLG)`) or if a step that ran before the abend needs to be re-run. Delete/uncatalog duplicates first.
  2. GDG Generation Bias Shift: Any `(+1)` dataset created and cataloged in a step prior to the abended step is now generation (0)!
  3. Temporary Datasets (`&&TEMP`) & `PASS`: All `&&TEMP` and `PASS` datasets were deleted when the original job abended. You must restart from the earliest step that created the required temporary dataset!
  4. Backward References (`DSN=*.STEP1.DD1`): Replace referbacks pointing to skipped steps with explicit `DSN=` names.
  5. PROC Step Restart Syntax: To restart inside a procedure step, code RESTART=jobstepname.procstepname.

Why Use DISP=(MOD,CATLG,CATLG) for Checkpoint/Restart?

In checkpoint-restartable batch programs (or multi-volume tape datasets), coding DISP=(MOD,CATLG,CATLG) serves two purposes:

  • On the first run, since the dataset does not exist, `MOD` allocates it as `NEW`.
  • If the step abends mid-way, abnormal disposition `CATLG` catalogs the partial file so the checkpoint-restart run can locate it via `MOD` and resume appending or repositioning from the last DB2/IMS commit point!
★ Senior Missing Notes — Restart / recovery / schedulersSenior note

Senior point: JCL restartability and scheduler restartability are related but not identical. RESTART=STEPNAME[/PROCSTEP] controls where JES resumes job processing; scheduler products may add their own restart/rerun semantics, so document both layers. Do not assume a scheduler rerun is equivalent to a JES restart.

Short JCL example
//PAYJOB JOB ...,RESTART=STEP03
//STEP01 EXEC PGM=LOAD1
//STEP02 EXEC PGM=CHECK1
//STEP03 EXEC PGM=LOAD2

Mental Anchor #2 • First-Letter Association

Never Confuse SB37, SD37, and SE37 Again

SB37 B = Bound by 16 Extents / Vol Full

"Both Primary & Secondary exhausted"

Dataset took its Primary allocation AND kept taking Secondary allocations until it either hit the 16-extent per volume limit (or 123 for SMS extended) OR the DASD volume ran out of free space.
Fix: Increase primary/secondary space or add multi-volume count VOL=(,,,5).

SD37 D = Direct Primary Only (No Sec!)

"Didn't code a Secondary allocation!"

Primary space filled up, z/OS tried to take a secondary extent, and discovered SPACE=(CYL,(50,0)) (zero secondary space specified!).
Fix: Add a secondary allocation quantity in SPACE=(CYL,(50,20)).

SE37 E = End of PDS Dir / Multi-Vol

"Exceeded PDS Directory or Volumes"

Either a PDS ran out of Directory Blocks (or hit 16 extents needing compress), OR a multi-volume dataset exhausted all specified volumes.
Fix: Compress PDS via IEBCOPY, reallocate with more directory blocks, or convert to DSNTYPE=LIBRARY (PDSE).

Mental Anchor #3 • 2x2 Matrix

GDG Roll-Off Options When LIMIT Is Reached

1. NOEMPTY (Catalog Action)

NOEMPTY = Next oldest only is uncataloged when limit is reached. (99% Production Default).

2. EMPTY (Catalog Action)

EMPTY = Everything (ALL generations) uncataloged from base when limit is hit!

3. SCRATCH (DASD VTOC Action)

SCRATCH = Shred physically from DASD VTOC immediately after uncataloging.

4. NOSCRATCH (DASD VTOC Action)

NOSCRATCH = Not deleted from disk; stays on volume VTOC as an uncataloged dataset.

Mental Anchor #4 • Hierarchy & Chameleon Rule

Program Load Search Order & DISP=MOD

1. STEPLIB (If coded, completely bypasses JOBLIB!)
2. JOBLIB (Searched ONLY if step has no STEPLIB)
3. LPA / Dynamic LPA (In-memory shared system modules)
4. LINKLIST (System LNKLST concatenation)
The DISP=MOD Chameleon Flowchart:
• Dataset exists in Catalog? ➔ YES: Positions pointer at EOF and appends records.
• Dataset does NOT exist? ➔ NO: Morphs into DISP=NEW and creates the dataset (requires SPACE/UNIT).
• Used in IEFBR14 with DISP=(MOD,DELETE,DELETE): Safely deletes dataset whether it exists or not!
